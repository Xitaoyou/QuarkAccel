夸克网盘下载器 v2 — 交付清单
================================

【直接能用】
  quarkgui\dist\QuarkAccel.exe        单文件 10.2 MB，双击即可，不需要装 Python
  quarkgui\dist\QuarkAccel-旧版tkinter.exe   上一版界面，留作备份

  ⚠ 必须放在可写目录（桌面 / 下载 / 文档都行）。放 C:\Program Files 起不来：
    单文件版启动时要先把自己解压到 exe 同目录，那里没有写权限。
    实测四种解压目录，只有「exe 同目录」稳定：默认 %TEMP% 报
    "Could not create temporary directory!"，指到 %LOCALAPPDATA% 报
    "CreateDirectory: 拒绝访问"（最小 hello 程序同样如此，是环境拦截）。

【第一次打开会白一下，正常】
  只有在需要降级参数的机器上，第一次会白约 9 秒：程序在探测渲染环境，探测不到
  就自动换一套参数重启 Edge。结果会记住，之后每次冷启动约 1 秒直出界面
  （含单文件解压合计 1.9 秒左右）。

【点「登录」不会再卡、不会弹黑框】
  登录窗口 0.3 秒出二维码，重复点会复用同一个窗口（约 40 毫秒）。
  进程枚举与清理改走系统 API，不再调用 PowerShell，所以不会闪黑框。

【这一版界面改了什么】
  · 左上角换成夸克网盘官方图标 + 官方「夸克网盘」字标 + 「下载器」，副标题删了
  · 应用图标换成官方客户端那只蓝 Q（7 个尺寸都重做过，任务栏/资源管理器里都清楚）
  · 顶栏不再是一叠白卡片，跟页面同底色，只有搜索框留一条淡描边
  · 左下角存储空间能显示了（登录后自动读网盘容量；演示模式给一组示例数字）
  · 产品名统一成「夸克网盘下载器」（窗口标题、exe 属性、任务管理器里都是）
  · 文件夹能点进去了：以前点进子目录会「面包屑变了、列表还是根目录」，现在
    每个目录都有自己的一份列表，面包屑每一级都能点回去

【导入分享链接】
  工具条点「导入链接」，粘 https://pan.quark.cn/s/xxxxxxxx?pwd=abcd 这种链接（提取码
  写在 ?pwd= 或粘在链接后面都行），点「先看看里面有什么」，它会把整个分享递归展开
  成文件清单；点「开始下载」就按清单下。

  清单里每个文件前面有复选框，默认全勾，取消掉的就不下（也不为它转存、不占空间）。
  下面一行实时显示「已选 12 / 48 个 · 1.2 GB」，按钮变成「下载选中的 12 个」；
  左边有「全选 / 全不选」。文件特别多时清单只列前 500 个，这时点全选是「全都要」，
  不会漏掉没列出来的。

  两条通道，按「哪条更快」自动选：
    · 没登录 + 文件 ≤ 48 MB → 免转存直下（不写你的网盘），但这条游客通道被限速
      到约 0.3 MB/s，慢
    · 已登录（能读到网盘容量）→ 先转存进网盘的「QuarkAccel-临时转存」目录 → 走
      加速通道分片并发拉回来 → 每批下完自动删掉，收尾连临时目录一起删
    · 没登录 + 文件 > 48 MB → 会提示先登录（分享直链对 50 MB 以上的文件直接拒绝）

  为什么登录后连小文件也走转存：游客直链是另一套 CDN，实测单流 0.49 MB/s、8 并发
  直接超时；自己网盘那条链实测能到 47.7 MB/s。差距太大，所以宁肯多花两秒转存。

  分批：一批最多 8 GB / 100 个文件，超过可用空间会自动切批（转存一批 → 下完 →
  删 → 下一批）。单个文件比整个可用空间还大的会跳过并列出来。
  中途点「停止」：正在下的任务逐个取消，等 3 秒收尾，不会留半截文件在网盘里。
  清单里每行右侧有标记：绿色「直下」= 免转存，黄色「转存」= 需要先转存。

【用起来什么样】
  左侧导航        全部文件 / 最近 / 视频 / 图片 / 文档 / 音频 / 收藏 / 我的分享 / 回收站 / 我的备份
  顶部            搜索框、账号胶囊（点它登录）、刷新、打开下载目录
  中间列表        勾复选框或点文件名都能选中；勾目录会递归展开整个子树
  视频行悬停       右边冒出播放键 ▶，点它边下边播（不用等整个文件下完）
  右下闪电按钮     打开「传输加速」抽屉

  传输加速抽屉里：
    · 四档卡片：标准 / 极速（默认）/ 自适应 / 自定义（选它后出现三个输入框）
    · 三个统计块：实时 MB/s、总进度、传输中任务数
    · 保存目录（点一下能改；启动时发现这个目录写不进去会自己换到数据目录下的
      downloads，并弹一句提示，免得你以为文件下丢了）；右侧「打开」直接跳资源管理器，
      目录不存在会先建，建不出来同样退到程序数据目录下的 downloads
    · 任务 / 下载记录 两个标签页
       任务页：每行文件名 + 状态 + 进度条 + 已下/总大小 + 速度 + 剩余时间，
               右侧按状态给按钮 —— 传输中/排队：暂停·×取消；已暂停：继续·×移除；
               完成：打开（资源管理器里选中它）·删除·×移除；失败：重试·删除·×移除
       记录页：完成 / 失败 / 取消都会留一条，按时间倒序，点一条直接定位到文件，
               每行右侧红色「删除」连磁盘文件一起删（确认框里带文件名和大小）
    · 底部：全部暂停 / 全部继续、清理已结束
    · 抽屉右上角那个 × 只关抽屉，不动任何任务；要动任务点任务行里的按钮

【四档参数】
  标准        128 连接 / 2 MB 切片 / 16 token   占用低
  极速（默认） 384 连接 / 1 MB 切片 / 48 token   设多少开多少，本机实测最快最稳
  自适应      384 上限 / 1 MB 切片 / 48 token   从 16 条起手，边下边试，自动找甜点
  自定义      8-384 连接 / 1-32 MB 切片 / 4-64 token，填大了会自动钳到上限

  前三个固定档都是直接铺满：选 384 就 384 条同时在飞，不做试探也不降档。
  只有连续撞上连接超时才折半回撤一次（保命），回撤后不再往上爬。
  自适应是单独一档，切过去才生效——几 MB 的小文件爬坡还没爬完就下完了，小文件用极速。

【速度参考（非会员，本机实测）】
  官方客户端                    0.10 - 0.35 MB/s
  本工具（默认极速档，384 条并发） 40 MB/s 上下，最低端 20 MB/s 以上
  课程目录批量（旧版固定并发）   48 文件 / 4.87 GB，31.1 分钟

  为什么以前只有 2 MB/s：连接数被钉死在 384 条，而夸克对同账号连接数有软上限。
  开到 384 条时握手阶段就开始超时，一批连接排队重试，吞吐反而塌下来。
  同一台机器、同一个 100 MB 对象的单点实测：
      8 连接   41.9 MB/s
     16 连接   43.1 MB/s
     32 连接   47.7 MB/s
     64 连接    1.7 MB/s
    128 连接    0.0 MB/s（400 次连接超时，一片都没下成）

  不知道甜点在哪就用「自适应」档：从 16 条起慢启动往上探，撞到不涨就二分收缩，
  收敛后钉住；连续两次连接超时立刻回撤，不等统计。抽屉里每个任务显示
  「N 连接」，那就是当前实际在飞的条数——停在 24 或 32 不是被限速。
  默认的「极速」档保持老手感：直接铺满 384 条，不试探不降档。

  同一段塌陷网络 128 MB 对照：固定 384 → 1.00 MB/s（128 秒）；
  自适应 → 9.84 MB/s（13 秒）；固定 16（理论上限）→ 10.66 MB/s（12 秒）。

【视频预览也是加速的】
  点播放键不是先下完再播，而是一边下一边播：文件切成 256 KB 小片，几十条连接
  并发往回拉，播放器每次要一段就直接从本地缓存命中。

  为什么必须这样：夸克按单连接限速（非会员 40-350 KB/s），视频码率本身就有
  40 KB/s 左右，浏览器又是按顺序请求的。实测同一条 40 KB/s 上游：
    直连           首帧「从未出画」，一直转圈
    并发预取预览    首帧 4.1 秒，之后 6 秒播到 7.0 秒，零卡顿

  三个细节（都是实测调出来的）：
    · 预览切片用 256 KB，比下载用的 1 MB 小：片越小第一帧来得越快
    · 开头 2 MB 再细分到 64 KB，保证最先到的是视频头
    · 先抢文件最后 1 MB：多数 MP4 的索引（moov）在末尾，没有它播放器连时长
      都不知道。这一条把首帧从 8.0 秒压到 4.1 秒

  点播放键时 src 和 play() 都在这次点击的手势里同步发出：等接口回来再 play，
  手势早就过期，浏览器会把播放拒掉，表现就是弹层里一直转圈、停在 0:00。

  播放器是整屏黑色弹层，右上角实时显示「已缓存 X / Y · N MB/s」，底部一条细
  进度条；Esc 或点背景关闭，关掉就停掉该文件的预取线程。
  浏览器不支持 mkv / rmvb / avi，这些点了会报错，直接下载看。

【登录】
  点右上角「未登录」→ 弹窗里「打开登录窗口」→ 独立浏览器里扫码登录
  → 回弹窗点「我已完成登录」→ Cookie 自动写入 exe 同目录 cookie.txt，登录窗口自动关

  也可以粘 Cookie：F12 → Network → 任意 drive-pc.quark.cn 请求 → 复制整行 Cookie: → 粘进弹窗

  为什么不能直接读浏览器 Cookie：新版 Chromium 把 Cookie 加密成 v20（App-Bound
  Encryption），密钥绑在浏览器进程上，外部解不出来。所以改成自己拉一个带独立
  profile 的 Edge，登录后走 DevTools Protocol 的 Storage.getCookies —— 由浏览器
  自己解密，拿到的就是明文。

【下载完整性】
  以前有个坑：下载器先把文件预分配成满尺寸，某轮彻底失败会留下「大小完全正确、
  内容全是 0x00」的假文件，重跑时被当成「已完整」跳过。课程目录就这么坏了两个
  （20.5 MB 的解析.pdf、1048.6 MB 的 .7z.001）。

  现在三层防护：
    1. 失败退出时打 .qbad 标记，下次见到直接重下
    2. 全部片下完后再拉远端头/中/尾各 64 KB 与本地逐字节比对，不一致就判失败
    3. 跳过已存在文件前先跑同样的比对，不过就「校验不过，重下」

【这一轮修掉的 bug】
  代码做了一遍完整审阅，改掉的高危项：
    · 边下边播：播放器 seek 时两条 Range 并发读同一个文件句柄，会读到错位字节
      → 读路径加锁；关闭时的 fd 也纳入同一把锁，杜绝句柄号复用读错文件
    · /media 先把 206 头发出去再取数据，取不到时 Content-Length 填不满，会让
      keep-alive 连接失步、播放器彻底卡死 → 改成「先取数再发头」，取不到回 503
    · 续传状态只记了「哪些片完成」，换切片尺寸后旧片号被当新片号 → 现在连文件
      大小和切片尺寸一起校验，不匹配就作废重下（经典假完成 bug）
    · 服务端忽略 Range 直接回 200 时，原实现会把文件开头写到片偏移处（静默花屏）
      → 现在判失败并留 .qbad；下载核心同步修，改成边收边写，去掉整片内存缓冲
      （自定义档 32 MB 片 × 384 连接原本峰值 12 GB）
    · 下载队列空档期 worker 重启竞态，新任务会永远停在「排队」→ 改用 _kick()
    · 单任务异常会打死 worker，任务永久卡在「运行中」→ 兜底 catch + 置 failed
    · 选目录走 PowerShell 时用 UTF-8 解 GBK 输出，中文路径被吃掉 → 统一编码
    · 调试端口改成默认关闭（CDP 无鉴权，任意本机网页可连上调 /api/*）
    · 点「取消」界面永久转圈：cancel() 在锁内又调了取同一把不可重入锁的 _finish()
      → 锁内只置状态，记录改到锁外写
    · 下载速度显示对不上：原来等整片下完才加计数，1 MB 片 + 384 连接时每秒跳两次、
      中间还有一段显示 0 → 改成每个连接收到字节就累加（bytes_rx 只增不减），界面按
      3 秒滑动窗口算增量；限速服务器对照实测误差在窗口抖动范围内
    · 右上角「打开下载目录」点了没反应：只调了 startfile，受限令牌下静默失败 → 依次试
      startfile → explorer → cmd start → PowerShell Shell.Application，并用 EnumWindows
      确认真的出了窗口；四种都不行时弹窗改「列目录内容 + 完整路径 + 复制按钮」，
      结论缓存住，第二次点击不再让用户等十几秒
    · 没有下载记录：完成/失败/取消现在都写 <数据目录>\downloads.json（最多 300 条，
      原子写），重启后还在

【这轮跑通的回归】
  · 本地 9.4 MB 随机文件：md5 一致、失败 0；conns/part 三组组合（8/1、64/2、16/4）全对
  · 服务端忽略 Range → 判失败并留 .qbad（不再静默花屏）
  · 预览 Range：后缀区间精确、谎报 size 被忽略、取数失败回 503 且连接不失步
  · 关预览后尾随 Range 回 503，不会重建流白下一整个视频
  · 队列：连续 6 次紧邻入队全完成、批量 12 个全完成、异常任务不影响后续
  · CDP：pong/70000 字节控制帧被正确跳过，业务响应能解出来
  · 实时速度：逐秒对照塌陷服务器，报告 17.73/19.55/19.05/15.37 对应实测
    18.06/20.74/15.68/15.24 MB/s；任务结束后数字立刻归零
  · 自适应并发：同一塌陷网络 128 MB，固定 384 → 1.00 MB/s，自适应 → 9.84 MB/s，
    固定 16 → 10.66 MB/s，三组 md5 全对
  · 视频预览：打包 exe 真实点击播放键，画面出到 t=4.9 秒、640x360、paused=false
  · 暂停 / 继续：CDP 真实点击任务行按钮，点下去状态立刻变 paused、速度归零，
    继续后回到 queued 并接着下（不是从头），其他任务不受影响
  · 取消：暂停中的任务直接取消也能立刻变 canceled，下载器同步停掉，记录写「已取消」
  · 取消与记录：点 × → canceled → 立刻出现在下载记录并标红「已取消」
  · 记录持久化：写完 4 条后杀进程重启，抽屉里仍是 4 条
  · 打开下载目录：目录不存在先建；受限令牌下自动退回数据目录，界面同步显示新路径；
    四种启动方式全被拦时弹窗列出目录内容并允许复制路径，第二次点击 0.0 秒返回
  · 删除本地文件：打包 exe 真实点击，磁盘文件 + .qstate/.qbad 一起删、toast 报释放大小、
    行从记录里消失；正在跑的任务拒绝删除；文件早就不存在时返回 missing 不算失败
  · 四档参数：切到自适应时 profile.adaptive=true，切回标准/极速/自定义都是 false，
    连接数/切片/token 各自回显正确
  · 全部暂停 / 全部继续：整体开关生效，按钮文案随状态切换
  · 打包 exe 全流程：onedir 版 CDP 走完勾选→下载→暂停→继续→取消→查记录，0 报错
  · 不设调试端口时 Edge 命令行无 --remote-debugging-port，界面照常

【原理一句话】
  服务端按「单连接」整形带宽，不限并发。所以把文件切成 1 MB 片、开几百条连接
  同时拉，总吞吐就是单连接的几十倍。翻遍 alist/OpenList 源码和客户端 asar，
  没找到整条不限速的通道——这不是可提权的漏洞，只是限速粒度太粗。
  完整分析在 quark-limits.md。
