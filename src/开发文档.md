# 夸克网盘下载器 v2（QuarkAccel）

Windows 桌面版夸克网盘下载器。界面是**夸克网盘风格的网页界面**，跑在本机的 Edge 应用窗口里（`--app` 模式，没有地址栏和标签页，看起来就是一个原生桌面程序）。

只管下载，不碰会员、不传文件、不删文件。

---

## 一、直接运行（不用装 Python）

1. 双击 `dist\QuarkAccel.exe`
   - **只有第一次**可能要等一会儿：这台机器的环境需要降级参数时，会先白 9 秒再自动重启一次 Edge（见「六、已知边界」）。结果会记进配置，**之后每次冷启动约 1 秒**直出界面。
   - 首次启动含单文件解压，合计约 1.9 秒。
2. 右上角「未登录」胶囊 → 点它 → 弹窗里点「打开登录窗口」→ 在独立浏览器里扫码登录 → 回弹窗点「我已完成登录」
   - 登录窗口 0.3 秒就绪；点第二次会复用同一个窗口（约 40 ms），不会重复开
   - Cookie 会自动取到并写入 exe 同目录的 `cookie.txt`，登录窗口自动关闭
   - 也可以直接粘 Cookie：F12 → Network → 任意 `drive-pc.quark.cn` 请求 → 复制整行 `Cookie:`
3. 左边导航筛分类，中间列表勾选文件（点复选框或点文件名都行，勾目录会递归展开整个子树）
4. 点「下载所选」→ 右下角闪电按钮打开「传输加速」抽屉 → 看实时速度 / 总进度 / 每文件进度条
5. 「传输加速」抽屉里四档任选，默认 **极速**（固定 384 条并发）；想让它自己找甜点就切 **自适应**

关掉再开、勾同一个文件会接着下：完整文件会被跳过（跳过前会拉远端头/中/尾三段逐字节比对），半截文件按分片续传。

## 三、四档传输

| 档 | 连接 | 切片 | token 池 | 说明 |
|---|---|---|---|---|
| 标准 | 128 | 2 MB | 16 | 占用低，边下边干别的 |
| **极速（默认）** | **384** | **1 MB** | **48** | 设多少开多少，本机实测最快最稳 |
| 自适应 | 384 上限 | 1 MB | 48 | 从 16 条起手，边下边试，自动找这台机器/这条线路的甜点 |
| 自定义 | 可调 8–384 | 1–32 MB | 4–64 | 切到「自定义」后下方出现三个输入框 + 应用按钮 |

为什么是 384 / 1 MB / 48：服务端限速是**按单连接**整形，所以切片要小、token 池要够。

切片必须小：同样 512 连接，1 MB 切片 1.398 MB/s，4 MB 切片只有 0.305 MB/s（4.6 倍差距）。
token 池也必须够：同一文件 8 连接，单链 0.351 MB/s → 每连接独立 token 0.893 MB/s。

三个固定档都是**直接铺满**：选 384 就是 384 条同时在飞，不做任何试探和降档。只有连续撞上
连接超时（说明线路/账号被限了）才折半回撤一次，回撤后也不再往上爬——那是保命，不是寻优。

### 自适应档：并发不是越多越快

单独一档，切过去才生效。真机上经常出现「384 条只有 2 MB/s，16~32 条能跑 40 MB/s 以上」，
原因不是带宽，是 CDN 对同账号连接数有软上限：开到 384 条时握手阶段就开始超时，一批连接
排队重试，吞吐直接塌到 1 MB/s 量级。

这一档里下载器自己找甜点（`quark_core.py` 里的 `Governor`，`on=True`）：

1. **慢启动**：从 16 条起，吞吐涨就往上探（×1.5），撞到第一次不涨为止，得到「好档 / 坏档」；
2. **二分收缩**：在区间里取中点试探，比好档快就抬下界，否则压上界，区间小于好档/8 就收敛钉住；
3. **连接超时是硬证据**：连续两次超时立刻回撤并封上界，不等窗口统计；
4. **换档丢一个窗口**：新旧档混在一起的窗口既不代表旧档也不代表新档，必须作废重测。

抽屉里每个任务会显示「N 连接」，那就是当前实际在飞的连接数——自适应档里看到它停在 24 或 32
不是被限速，是控制器已经认定这是最快的那一档。

**什么时候别用自适应**：几 MB 到几十 MB 的小文件，爬坡还没爬完文件就下完了，反而比固定档慢。
小文件用「极速」；几百 MB 以上、或者你不确定自己这条线路的甜点在哪，再用自适应。

| 场景（本地复现 CDN 塌陷模型：16 条内线性、超过 16 条按比例衰减、48 条握手卡死） | 平均速度 |
|---|---|
| 固定 384 连接（旧行为） | **1.00 MB/s**（前 5 秒 19 MB/s，之后塌到 0.7，靠长尾慢慢爬，128 MB 用 128 秒） |
| 自适应并发（新） | **9.84 MB/s**（16 → 24 收敛，同样 128 MB 用 13 秒） |
| 固定 16 连接（理论上限） | 10.66 MB/s（12 秒） |

同样一段塌陷网络里，**自适应比死磕 384 快约 10 倍**，而且不用用户自己猜档位。
真机 100 MB 对象的单点实测（同一时段、同一对象）：8 连接 41.9 MB/s、16 连接 43.1 MB/s、
32 连接 47.7 MB/s、64 连接 1.7 MB/s、128 连接 0 MB/s（400 次 ConnectTimeout，一片都没下成）。

### 速度是实时算的，不是估的

每个连接收到多少字节就当场累加（`quark_core.py` 里的 `bytes_rx` 只增不减），界面按 3 秒滑动窗口算增量：

```
speed = (当前累计 - 窗口起点累计) / 1MB / 窗口时长
```

以前是等整片下完才加 `bytes_done`，1 MB 片 + 384 连接时数字每秒跳两次、中间还有一段显示 0，跟实际差很远。

现在按「服务器真的发出了多少字节」对照（本地塌陷服务器，逐秒记录）：报告值与实测差值大多在 1 MB/s 以内，
稳态几秒分别是 `18.06 → 17.73`、`20.74 → 19.55`、`15.68 → 19.05`、`15.24 → 15.37` MB/s。
任务停下来（下完 / 暂停 / 卡住）后速度立刻归零——早期版本会把最后那个数一直挂在界面上，看起来像虚报。

重试回滚只影响进度（`bytes_done` 会退），不影响速度曲线（`bytes_rx` 继续累加），网络抖动时数字不会突然砸到 0。

### 暂停 / 取消 / 重试 / 移除

| 动作 | 语义 | 续传 |
|---|---|---|
| 暂停 | 立刻把状态置 `paused`、速度清零，同时给 Downloader 发 stop（不等当前分片收完，否则界面会挂着 20 MB/s 看着像没反应） | 靠 `.qstate` 记已完成片号，继续时只拉剩下的 |
| 继续 | `paused` → `queued`，worker 重新拾起 | 同上 |
| 取消 | 置 `canceled`，不再参与队列；同时给 Downloader 发 stop 并清掉 paused 标记（否则界面显示已取消、后台还在写盘） | 不会自动续；想续得重新加任务 |
| 重试 | 删 `.qstate` / `.qbad` 后重排（正在跑的任务不允许重试，避免写盘途中删状态） | 从头下 |
| 移除 | 只从列表里删，不删磁盘文件 | — |

底部的「全部暂停 / 全部继续」是整体开关：置 `Engine.paused`，worker 每 0.3 秒看一次，暂停期间不取新任务。

### 下载记录

完成 / 失败 / 取消都会写一条到 `<data_dir>/downloads.json`（最多 300 条，原子写：tmp + `os.replace`），抽屉第二个标签页「下载记录」按时间倒序列出，点任意一条在资源管理器里定位到文件。重启后记录还在；「清理已结束」只清列表不动记录，`clear_hist` 才是清记录。

### 删除文件（连磁盘一起删）

任务行（已结束的）和「下载记录」行都有红色的「删除」。点了先弹确认框，**写着文件名和大小**，确认后：

1. 删 `<文件>`、`<文件>.qstate`（续传断点）、`<文件>.qbad`（坏片记录）；
2. 从任务列表 / 下载记录里摘掉；
3. toast 报「已删除 xxx，释放 221.0 MB」。

接口是 `api('delete', {id})`，后端 `Engine.delete_files(jid)`（`shell/engine.py`）。**只按任务 id 取路径，界面传路径一律不接**——否则这条接口就等于「任意文件删除」。

![删除确认](ui/v3/07-删除确认.png)

三种拒绝：正在跑的任务（先取消）、id 找不到、删的时候被占用（返回 `删不掉 xxx：...`，文件还在）。返回体带 `freed`（真删掉的字节数）和 `missing`（文件早就不在了），所以重复点同一条不会报错。

### 「打开下载目录」在受限环境里的兜底

正常环境下 `os.startfile` 就打开了。但如果程序本身跑在一个受限令牌里（本机实测：`os.startfile` 抛 `PermissionError [WinError 5]`、`explorer /e,` 返回 `0xC0000142 STATUS_DLL_INIT_FAILED`、`ShellExecuteW` 返回 5），那不管换哪种启动方式都起不来资源管理器。

`shell_open()`（`shell/app2.py`）依次试 startfile → `explorer` → `cmd /c start`（5 秒超时）→ PowerShell `Shell.Application.Explore`（8 秒超时），并且**用 `EnumWindows` 数一遍有没有真的出现窗口**——只看返回码会被骗（`cmd start` 返回 0 但桌面什么都没有）。全部失败才认定打不开，结论缓存进 `self._open_bad`，第二次点击 0.0 秒直接返回，不再让用户等十几秒。

失败时弹「打开目录」对话框，做两件事替代资源管理器：

- **列出该目录的内容**（`api('dir_list', {limit})`，跳过 `.qstate` / `.qbad`，带大小和时间），至少能看见文件下到哪了；
- **显示完整路径 + 复制按钮**（`navigator.clipboard` 失败时回落到 `textarea + execCommand`），粘到别的地方就能打开。

## 三点五、视频预览也走并发（`shell/stream.py`）

点播放键不是把整个文件下完再播，而是**边下边播**：`Stream` 把文件切成片丢进队列，几十个连接并发往回拉，播放器每次请求一段 `Range` 就直接从本地缓存命中。

为什么必须这么做：夸克按**单连接**整形（非会员 40–350 KB/s）。视频码率 350 kbps ≈ 44 KB/s，浏览器又是按顺序请求 `Range` 的，单连接刚好卡在码率上下——网络稍抖就永远缓冲不出第一帧。实测同一条 40 KB/s 上游：

| 方式 | 首帧 | 首帧后 6 秒播到 | 卡顿 |
|---|---|---|---|
| 直连（浏览器单连接） | **从未出画** | 0.0 s | — |
| 并发预取预览 | **4.1 s** | 7.0 s | 0 |

整文件吞吐对照（200 KB/s/连接，12.91 MB）：1 路 0.78 MB/s → 32 路 **4.95 MB/s（6.4 倍）**。

三处关键调优，都不是拍脑袋：

1. **预览切片用 256 KB，不用下载那套 1 MB**。片是「就绪」的最小单位，片越大第一帧等越久。
2. **开头 2 MB 再细分到 64 KB**（斜坡），保证最先就绪的几片正好覆盖 `ftyp` + 首个 `mdat` 分片。
3. **先抢文件尾部 1 MB**。多数 MP4 的 `moov`（时长、索引）在文件末尾——实测 `.tmp/probe.mp4` 的 `moov` 在偏移 13521724（总长 13534752），不先拿到它，播放器连视频多长都不知道，`readyState` 永远是 0。这一条把首帧从 8.0 s 压到 4.1 s。

服务端 `/media/<fid>` 是标准 HTTP Range 实现：`206 + Content-Range + Accept-Ranges`，越界回 `416 bytes */<size>`，`HEAD` 也给正确的长度。单次最多回 1 MB（`MEDIA_SPAN`），开头只回 1 MB（`MEDIA_FIRST`）——回太多等于让播放器等一整块凑齐才拿到数据，实测 4 MB 会让 6 秒里卡 2 次。

缓存：`Pool` 管多个文件，LRU 保留最近 2 个（`max_items=2`），关播放器就 `media_stop` 停掉该文件的线程。缓存文件在 `<data_dir>/cache/`。

演示模式也能播：假数据里有一条 `demo-20s.mp4`（1.0 MB，ffmpeg 生成的 testsrc2 彩条），走 `LocalReader` 直接从磁盘喂，不联网。

## 三点六、导入分享链接（`shell/importer.py`）

别人给你一条 `https://pan.quark.cn/s/xxxxxxxx?pwd=abcd`，不用先手动转存再挑文件：工具条点「导入链接」，粘进去，点「先看看里面有什么」，它会把整个分享**递归**展开成文件清单，标出每个文件走哪条通道，然后一键下完。

清单是**可勾选**的：每个文件前面一个复选框，默认全勾；取消掉的不会下（也就不会为它转存、不会占空间）。下面一行显示「已选 12 / 48 个 · 1.2 GB」，按钮跟着变成「下载选中的 12 个」。左边还有「全选 / 全不选」两个快捷操作。分享里的文件特别多时清单只列前 500 个，这时点「全选」下发的是「全都要」而不是那 500 个 fid —— 后端自己再列一遍，不会漏。

选中的集合只在真正启动时传给后端（`import_start` 的 `pick` 参数，fid 数组）：预览阶段只是列清单，不落盘、不转存。三种取值必须分清 —— `pick` 缺省 = 全都要（界面全选时走这条），`pick: []` = 一个都没勾（直接拦下，提示「一个文件都没勾选」），`pick: [fid…]` = 只下这些（分享内容变了、fid 对不上时给「没有匹配到勾选的文件」，而不是干跑一趟显示「完成 0 个」）。

两条通道，按「哪条更快」自动选：

| 情况 | 走的通道 | 速度 | 代价 |
|---|---|---|---|
| 没登录，文件 ≤ 48 MB | **免转存直下** | 约 0.3 MB/s（游客 CDN 限速） | 不占网盘空间，不写你的网盘 |
| 没登录，文件 > 48 MB | 下不了，提示先登录 | — | 分享直链对 >50 MB 返回 `23018 download file size limit` |
| 已登录（能读到网盘容量） | **转存 → 加速通道 → 下完删掉** | 几十 MB/s（分片并发那条链） | 临时占用网盘空间，结束自动删 |

登录态优先走转存不是偷懒：游客直链是另一套 CDN（`dl-guest-*.drive.quark.cn`），实测单流 0.49 MB/s、8 并发直接超时，同一个 5 MB 的 PDF 从 35 s 变成 1 s 量级，差距在十倍以上。所以只要登录了，小文件也照样走加速通道。

免转存直下是怎么做到的：`POST /file/share/download`（body `{fids:[fid], pwd_id, stoken}`）**不转存、不登录也能拿到直链**，stoken 来自 `/share/sharepage/token`（游客就能拿）。两个硬约束都踩过：

1. **体积上限约 50 MB**。5 MB / 10 MB / 19 MB / 42 MB / 44 MB 全通，399 MB 和 1000 MB 一律 `23018`。试过把 `range_size`/`range_start` 塞进 body、把 `range`/`size` 塞进 query，全部无效——上限是服务端按设备类型判的，不是 range 参数能绕的。代码里 `DIRECT_MAX = 48 << 20` 留了余量。
2. **必须带同一会话的游客 Cookie**。裸请求、干净 Session、Cookie 传空串一律 **412**（Tengine 的 262 字节 HTML 错误页）。而且这条 Cookie 里必须有 `__pugs`——它是 `/file/share/download` 那次响应才种下来的。所以 `Downloader` 里的 Cookie 头是**懒取**的：构造时算只有半条 `__sdid`，必然 412；`_ck(refresh=True)` 在每次重试前重新拼一次才行。

转存那条链：`ensure_dir("QuarkAccel-临时转存")` → `share_save` → 轮询 `task_wait` → 按容量分批（`BATCH_MAX = 8 GB`、`MAX_SAVE = 100` 个文件一批）→ 交给下载引擎 → 每批下完 `del_files` 删掉临时文件，收尾连临时目录一起删。中途点「停止」会逐任务 `cancel` 再等 3 秒收尾，不会留半截文件在网盘里。

校验口径：分享直链返回的那个 `md5` 字段**不是文件内容的 md5**（1 个 179666 字节的 PDF：接口给 `fd482b9a…`，真实内容 `c411607f…`）。真实值在 CDN 响应头 `Content-MD5`（base64），解码后才是。所以免转存直下的完整性校验一律用 `Content-MD5`，用接口那个 md5 会把好文件全判成坏文件。

真机实测（链接 `pan.quark.cn/s/d8ea7e22251e`，48 个文件 4.5 GB）：清单 48 个文件正确展开，游客态 43 个（2.5 亿字节）判为可直下、5 个（4.6 GB）要求登录；抽 3 个小文件走完整引擎链路下载，133 秒拿完 1.1 MB，三个文件的 md5 与 `Content-MD5` 全部一致（`RESULT DIRECT_OK`）。

界面上的提示都很直白：没登录时清单里每行右侧标绿「直下」或标黄「转存」，弹窗顶上一句「免登录这条通道是限速的（约 0.3 MB/s），登录后同样的文件走加速通道能到几十 MB/s」，点了「开始下载」还会实时显示进度条、已完成数量、当前在转存第几批。

> 调试端口默认关闭：只有显式设 `QA_DEV_PORT=9490` 启动时，Edge 才会带 `--remote-debugging-port`。CDP 没有鉴权，任何本机页面都能连上去 `Runtime.evaluate` 调 `/api/*`，所以正式运行时不开。

### 为什么界面不是 tkinter

试过 tkinter + sv-ttk 方案（见 [ui/界面重构方案.md](ui/界面重构方案.md)），能做出现代观感，但**所有控件都得自己画**：真复选框要 PIL 合成位图、每文件进度条要用 Canvas 替掉 Treeview、卡片圆角投影在 Tk 里根本做不到。

换成「本地 HTTP + Edge --app」之后：

- 界面用 HTML/CSS 写，圆角、阴影、渐变、flex 布局全是原生的
- 视觉可以 1:1 对齐夸克官网（token 直接抄）
- 与 `/api/*` 天然同源，零 CORS、零 PNA（页内 fetch `http://127.0.0.1` 会被 Private Network Access 拦死，反过来让页面自己从本机加载就没这个问题）
- `quark_core.py` 一行没改，下载引擎照样复用

### 为什么不直接套壳官方网页版

官方 `pan.quark.cn` 响应头带 `X-Frame-Options: SAMEORIGIN`，不能 iframe 套；注入浮层虽然可行（实测 `document.createElement` 能挂上去），但

- 官方网页版**没有传输/下载任务页**（`#/transfer`、`#/download`、`#/offline` 全回落到 `#/list/all`）
- 没有离线下载 / BT 新建入口
- 官方 SPA 一次改版，注入脚本就可能全部失效

所以做成**自己的界面 + 自己的引擎**，只借用它的视觉规范和 API。

### 为什么不全盘移植客户端前端

客户端 `app.asar` 里 `dist/renderer` 有 204 MB、1279 个文件，但重度依赖 preload 注入的 `ipcRenderer` / `webFrame` / `electron` —— 搬到浏览器里跑不起来。而且 `Quark.exe` 没有 Electron fuse sentinel，用 `--remote-debugging-port` 拉起后 `/json/list` 里只有 `chrome://new-tab-page` 和扩展 service worker，**主窗口根本不出现在 page target 里**，摸不到也改不了。

详见 [ui/界面重构方案-第二版.md](ui/界面重构方案-第二版.md)。

## 五、自己改 / 自己打包

```bat
cd quarkgui\shell
python make_icon.py         :: 需要改图标时才跑
python build2.py            :: 单文件 → dist\QuarkAccel.exe
python build_onedir.py      :: 目录版 → dist\QuarkDir\QuarkDir.exe（调试用）
```

打包参数必须带：

- `--add-data ui.html;.` —— 界面文件要打进包里
- `--runtime-tmpdir .` —— 单文件版启动要自解压，四种目标目录实测过：`%TEMP%` 报 `Could not create temporary directory!`，`%LOCALAPPDATA%\QuarkAccel\tmp` / `%TEMP%\QuarkAccel` / `%LOCALAPPDATA%\Temp\QuarkAccel` 报 `CreateDirectory: 拒绝访问`，只有 **exe 同目录**稳定可用（最小 hello 程序同样如此，是环境拦截不是项目问题）。代价是 exe 必须放可写目录
- `--icon app.ico --version-file version_info.txt`

在 MSYS bash 里直接敲 PyInstaller 会因为引号被吃报 `Wrong syntax, should be --add-data=SOURCE:DEST`，所以参数写在 .py 里用 subprocess 跑。

## 六、已知边界

- **只支持下载**，没有上传、分享、转存、离线下载、BT
- 非会员账号，服务端按单连接限速；并发能放大但**不能突破家宽**
- 某些环境（受限 Job / 受限令牌）里 Chromium 渲染进程起不来，表现是白窗口 → 程序 9 秒后自动带 `--no-sandbox --disable-gpu` 重启一次，并把结果写进配置，之后冷启动约 1 秒
- 登录窗口也用同一套自愈逻辑（0.3 秒就绪；白屏就换参数重启）；重复点会复用窗口，不会越点越多
- 视频预览只支持浏览器能解的容器（mp4/m4v/mov/webm/ogg）。mkv、rmvb、avi 这些浏览器原生不放，点了会报错——这种情况直接下载来看
- 预览缓存是「文件级 LRU」，最多同时留 2 个文件的缓存，超出会删最久没用的
- 演示模式：`set QA_DEMO=1` 或配置里 `demo: true`，用 12 条假数据看界面，不联网（其中 `demo-20s.mp4` 可真的播放）
- 单文件版必须放在**可写目录**（桌面/下载/文档都行），放 `C:\Program Files` 会因为解压运行时失败而起不来
- `--no-sandbox` 时 Edge 顶部会有一条黄色提示条；已用 `--test-type` 压掉
- 删除文件是真删（进不了回收站），所以确认框带文件名和大小；正在跑的任务不给删，得先取消
- 「打开下载目录」依赖系统壳；如果程序本身跑在受限令牌里，四种启动方式都会被系统拦掉，只能退化成「列目录 + 复制路径」
